KASSIGNER SECURITY FIX RECORD 015

Finding:
Temporary and shared secret-bearing buffers were not consistently erased.

Branch:
fix/complete-secret-zeroization

Affected files:
bootloader/src/ui/seed_manager.rs
bootloader/src/app/data.rs
bootloader/src/app/boot_test.rs
bootloader/src/main.rs
bootloader/src/handlers/menu.rs
bootloader/src/handlers/tx.rs
bootloader/src/handlers/stego.rs
bootloader/src/handlers/camera_loop.rs

Before:
Temporary SeedSlot values containing a mnemonic and passphrase had no Drop
cleanup and could remain on the stack after store returned.
The shared 128-byte jpeg_desc_buf could contain messages, commit/reveal
plaintext, decrypted plaintext, or an encryption password, but panic/shutdown
cleanup did not erase it.
Several paths reset jpeg_desc_len without erasing old bytes.
Some paths erased only the current length, leaving bytes from an earlier longer
secret beyond the new length.
Temporary secret-derived SHA-256 arrays were not explicitly erased.

After:
Every SeedSlot automatically performs volatile zeroization when dropped.
This includes temporary slots on successful and early-return paths.
A centralized clear_jpeg_description method wipes all 128 bytes and resets the
length with a compiler fence.
Panic/shutdown cleanup and commit/reveal cleanup call the centralized wipe.
Message, steganographic, SD-read, encryption-error, cancellation, and decrypted
result paths use the same full-capacity wipe instead of resetting length alone.
Temporary seed-derived, raw-key-derived, and message hash arrays are explicitly
zeroized after their required value is copied.

Verification:
The mandatory seed deletion test now checks every mnemonic, passphrase, length,
and fingerprint field is zero after deletion.
A mandatory AppData startup self-test fills all 128 shared bytes, clears them,
and requires every byte and the length to be zero. Failure shows SECRET WIPE
FAILED and halts the firmware.
Source search found no direct jpeg_desc_len = 0 assignments outside the
centralized wipe method.
Waveshare normal, verbose, and production builds passed.
M5Stack normal, verbose, and production builds passed.

Hardware verification remaining:
Flash the M5Stack verbose build and confirm startup passes the mandatory cleanup
self-test before release or publication.

Status:
Implemented and compiled locally. Not committed or pushed at the time this
record was created.
